# Анализ продукта: пробелы относительно аналогов и план улучшений

Назначение: честная карта того, чего не хватает Personal AI Hub по сравнению с
Open WebUI, LibreChat, TypingMind, AnythingLLM, LM Studio и Jan, и что улучшать
в первую очередь. Документ описывает фактическое состояние на текущий релиз
(Этап 1) и приоритизирует работу по ценности и стоимости.

Сравнительная база: self-hosted чат/рабочие пространства LLM. Ключевое отличие
Personal AI Hub — жёсткий контроль расходов (бюджет, Decimal, резервирование до
вызова) и режимы обработки данных (ADR-0007/0008). Это сильные стороны, которые
аналоги дают не всегда или дают слабее.

## 1. Что уже есть и повторять не нужно

- Запуск одной командой, миграции, healthchecks, structured JSON-логи, CI
  (ruff/mypy/pytest/tsc/eslint/gitleaks).
- Провайдеры (OpenRouter/RouterAI/Selectel/OpenAI-compatible + presets +
  sync-models с импортом цен), шифрование ключей мастер-ключом.
- Потоковый чат, отмена, экспорт MD/JSON, теги/архив/удаление/автонейминг.
- Бюджеты и расходы: резервирование до вызова, settlement по факту,
  estimated/actual/reconciled/unknown, дневной/месячный hard limit, закрытый
  billing-контур для embeddings и RAG-синтеза.
- Jobs/Assets, OCR (Tesseract + RapidOCR, ADR-0002), RAG с цитатами, таблицы
  (DuckDB sandbox), опциональный LiteLLM-профиль (ADR-0004).
- Режимы обработки (4), окно контекста, retention (ADR-0008), PWA-основа
  (ADR-0009).

## 2. Пробелы по темам

### 2.1 Пользовательские сценарии (высокий приоритет, средняя стоимость)

| Пробел | Сейчас | Что даст |
| --- | --- | --- |
| Редактирование и ветвление сообщений | `parent_id` есть в БД, UI нет | исправить вопрос → перегенерировать только ветку |
| Поиск по содержимому сообщений | только по названию/тегам, клиентский | поиск по тексту переписки (FTS), пагинация диалогов |
| Вложения и изображения в чате | кнопка задизейблена, vision нет | файлы и картинки в запросе (мультимодальный ввод) |
| Системный промпт в UI | `system_instruction` есть в API, редактора нет | персональные инструкции на диалог |
| Параметры генерации | только глубина рассуждений | temperature/max tokens/top_p на диалог |
| Библиотека промптов | нет | переиспользуемые шаблоны |
| Горячие клавиши | нет | быстрая навигация и отправка |

### 2.2 Качество RAG (средний приоритет)

- Reranking и гибридный поиск (сейчас только dense + порог `MIN_RELEVANCE`).
- Структурный чанкинг по заголовкам (сейчас фиксированное окно 2000/200).
- Golden-тесты retrieval (в integration — векторы-заглушки).
- Объединение таблиц и документов в одном ответе.

### 2.3 Эксплуатация и дистрибуция (высокий приоритет для обычного пользователя)

- PWA-установка и Windows-инсталлятор — закрываются ADR-0009.
- UI для backup/restore (есть только скрипты `infra/scripts/*.sh`).
- UI журнала аудита защищённых операций (есть только API).
- In-app подсказка об обновлении версии.
- Однопользовательский режим — осознанное ограничение (не пробел): один admin,
  нет профилей/наборов ключей/общего доступа.

### 2.4 Интерфейс

- Локализация только русская (i18n — на будущее).
- Сравнение моделей side-by-side, управление prompt-кэшем.
- Onboarding уже есть; добавить ссылку на краткую инструкцию.

### 2.5 Крупное (отложено)

- Этап 2 «Video» (ROADMAP 9–14).
- Многопользовательский режим и роли.
- Встроенный локальный рантайм с менеджером моделей (сейчас `local_only`
  работает с внешними Ollama/LM Studio, без загрузчика моделей).
- Нативный bundle без Docker (ADR-0009, вариант D).

## 3. Рекомендуемый порядок улучшений

1. **ADR-0009**: PWA + Windows-инсталлятор (в работе).
2. Редактирование/ветвление сообщений + параметры генерации (быстрая ценность
   для ежедневного чата).
3. Вложения и изображения (vision) — следом за мультимодальным провайдером.
4. Поиск по сообщениям + пагинация (перейти к серверной фильтрации).
5. Reranking/структурный чанкинг + golden-тесты retrieval.
6. Backup/restore и аудит в UI.

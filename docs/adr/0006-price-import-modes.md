# ADR-0006: Режимы импорта тарифов — LLM-извлечение и headless-рендер

- **Статус:** принято
- **Дата:** 2026-10-19
- **Связанные решения:** ADR-0002 (измерение стоимости тяжёлых зависимостей),
  ADR-0004 (опциональный сервис в compose-профиле), ADR-0005 (веб-поиск)

## Контекст

Статический разбор страницы тарифов (ADR-0005, модуль `pricing_import`) читает
HTML и ищет цены регулярными выражениями. Этого достаточно для страниц
документации, где таблица есть в разметке (например, DeepSeek). Но:

- часть площадок дорисовывает таблицу JavaScript — в скачанном HTML цен нет;
- часть страниц описывает цены текстом или нестандартной вёрсткой, и регулярки
  не находят ничего.

Пользователь оставался с нулём кандидатов и вводил цены вручную.

## Рассмотренные варианты

1. **Только LLM-извлечение** (модель читает текст страницы).
   Плюс: понимает произвольный текст. Минусы: платно, числа могут быть
   перепутаны, а для самой первой модели упирается в замкнутый круг: платный
   вызов запрещён без цены, а мы как раз ищем цену. Поэтому как единственный
   путь не годится.
2. **Только headless-браузер** (Chromium исполняет JS и отдаёт готовый текст).
   Плюс: числа берутся из фактической разметки, а не из пересказа. Минусы:
   тяжёлый образ, не помогает для нестандартного текста без таблиц.
3. **Внешний сервис рендера** (чужой API). Отклонено: пользовательские URL
   уходят третьей стороне, зависимость и приватность хуже, чем у локального
   контейнера.
4. **Ничего не добавлять.** Отклонено: пользователь вынужден вручную переносить
   цены, что и было исходной проблемой.

## Решение

Три режима одного эндпоинта `POST /api/v1/prices/extract` (поле `method`):

| Режим | Что делает | Стоимость | Когда применять |
| --- | --- | --- | --- |
| `static` (по умолчанию) | HTML → текст → регулярки | бесплатно | обычные страницы документации |
| `rendered` | Chromium открывает страницу, исполняет JS, отдаёт текст, тот же разбор | бесплатно, но медленно | таблица дорисовывается скриптами |
| `llm` | модель извлекает цены в строгий JSON | платно, через бюджет | нестандартный текст, где регулярки бессильны |

Во всех режимах результат — **кандидаты**, которые пользователь обязан
сверить и сохранить отдельным действием. Ничего не сохраняется автоматически.

### LLM-извлечение: денежная дисциплина

- Модель выбирается явно или берётся первая модель пользователя **с заданной
  ценой**. Без цены платный вызов невозможен (strict billing), и API отвечает
  понятной ошибкой, а не тихо работает мимо бюджета.
- Резерв создаётся **до** обращения к провайдеру, при ошибке освобождается,
  при успехе фиксируется `UsageRecord` с операцией `price_llm_extract`.
  Если провайдер вернул usage — состояние `actual`, иначе `estimated`.
- Расход фиксируется **до** разбора ответа: вызов уже оплачен, даже если
  модель вернула мусор.
- Контракт ответа — строгий JSON с четырьмя полями. «Не знаю» — это `null`,
  а не ноль: нулевая цена исказила бы учёт расходов. Неизвестные поля
  отбрасываются, отрицательные и абсурдные значения превращаются в `null`.
- Текст страницы помечается как данные: инструкция запрещает выполнять команды
  со страницы (prompt injection) и требует не выдумывать числа.

### Headless-рендер: отдельный сервис

Сервис `pricebot` (compose-профиль `pricebot`, `make up-pricebot`):

- Chromium + Playwright в **отдельном** контейнере. В образ API браузер не
  добавляется: он тяжёлый, исполняет чужой JavaScript и не должен соседствовать
  с процессом, владеющим ключами и базой.
- SSRF: адрес проверяется тем же правилом, что и статическая загрузка
  (только публичные http/https, приватные и loopback диапазоны запрещены).
- Перехват всех запросов страницы: разрешены только тот же домен и служебные
  схемы (`data:`, `blob:`, `about:`). Сторонние домены блокируются — меньше
  исходящих соединений и трекеров.
- Свежий контекст на каждый запуск: без кук, без сохранённого состояния.
- Ограничения: таймаут загрузки (по умолчанию 25 с), длина текста 200 КБ,
  одновременный рендер — один (Chromium прожорлив по памяти).
- Автоматический фолбэк: если `static` не нашёл цен, а сервис включён,
  платформа сама пробует `rendered` и сообщает метод в ответе.

## Измерения (2026-10-19, Docker Desktop, x86-64, Windows)

| Показатель | Значение |
| --- | --- |
| Образ `pricebot` (`playwright install --with-deps chromium`) | **1,96 ГБ** |
| Образ slim-варианта (ручной список библиотек, без `--with-deps`) | 1,82 ГБ (−140 МБ) |
| Базовый образ API для сравнения | 821 МБ |
| Время рендера страницы тарифов DeepSeek | **3,4–4,2 с** |
| Память контейнера в покое | **169 МиБ** |
| Пиковая память во время рендера | **393 МиБ** |
| Текст страницы после рендера | ~3,2 КБ |
| Кандидатов из DeepSeek (peak и off-peak, две модели) | 12 |

Slim-вариант отклонён: экономия 140 МБ не оправдывает ручной список системных
библиотек, который придётся поддерживать при каждом обновлении Chromium.
Рост образа API при этом равен нулю — сервис опционален и не входит в базовый
стек.

## Последствия

- Базовая установка не меняется: без профиля `pricebot` сервис не
  запускается, `PRICEBOT_ENABLED=0` по умолчанию, режим `rendered` отвечает
  понятной ошибкой.
- Появляется третий опциональный сервис (после LiteLLM и SearXNG); в отладке
  нужно помнить про три независимых профиля.
- LLM-режим добавляет платный путь: он проходит через существующий бюджетный
  контур, нового учёта не потребовалось.
- Автоматический разбор по-прежнему не гарантирует правильность: на странице
  обычно несколько моделей и тарифов (peak/off-peak), поэтому кандидатов
  бывает много и выбор остаётся за пользователем.
- Защита от ботов (Cloudflare) может отдать заглушку вместо таблицы — сервис
  вернёт понятную ошибку, а не пустой результат.

## План rollback

`PRICEBOT_ENABLED=0` отключает режим `rendered` и фолбэк; `make down-pricebot`
останавливает сервис. Режим `llm` отключается отсутствием модели с ценой.
Статический разбор и сохранение цен продолжают работать без изменений.

## Влияние на Этап 2 (video generation)

Отсутствует: решение не затрагивает контракты `Provider`, `Job`, `Asset`,
`UsageRecord`, `BlobStore`.

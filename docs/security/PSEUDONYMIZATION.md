# Псевдонимизация: алгоритм, псевдонимы, восстановление

Назначение: описать, как именно работает обратимая замена (ADR-0007) и что
происходит при потере карты. Документ относится к реализованным срезам 1–5.

## 1. Общая схема

```text
текст → детектор (spans) → sanitizer → sanitized-текст → внешняя модель
                                ↓
                          EntityVault (шифротекст в PostgreSQL)
                                ↓
ответ модели → restore(точное совпадение) → текст для пользователя
```

## 2. Детектор

- Регулярные выражения: email, телефон, URL, СНИЛС, ИНН, ОГРН, БИК,
  расчётный счёт, паспорт, адрес, секреты (ключи, пароли, `Bearer`).
- Словарь пользователя: названия организаций и объектов; сравнение без учёта
  регистра, длинные значения проверяются первыми.
- Пересечения разрешаются по приоритету и длине: секрет важнее URL, длинное
  название важнее короткого.
- Чего нет: NER-модели, поэтому имена людей не распознаются; реквизиты без
  подписи могут пропускаться.

## 3. Псевдонимы

- Формат: `[CATEGORY_N]`, например `[ORG_1]`, `[EMAIL_1]`, `[PHONE_1]`.
- Нумерация — в пределах области (ревизия диалога), поэтому одинаковое значение
  получает одинаковый псевдоним, а разные организации — разные номера.
- Псевдонимы не угадываются: восстановление возможно только по записи в vault,
  а не по шаблону строки.
- Секреты не получают псевдоним: они удаляются маркером `[удалено]`.

## 4. Хранение

- `protection_preparations` — подготовка: digest приватного payload, ревизия,
  срок жизни, построчные sanitized-сообщения.
- `protection_entities` — vault: псевдоним, категория, шифротекст
  (мастер-ключ приложения, Fernet-контур).
- Открытых значений в базе нет; API не имеет эндпоинта расшифровки.

## 5. Восстановление

- Только точное совпадение псевдонима из vault.
- Без рекурсии: подставленный текст повторно не сканируется.
- Внутри URL, markdown-ссылок и HTML-тегов псевдонимы не восстанавливаются.
- Неизвестный псевдоним остаётся как есть и попадает в список пропущенных.
- Streaming-восстановление придерживает хвост, похожий на начало псевдонима или
  незавершённый URL, чтобы не показать половину токена и не подставить значение
  внутрь ссылки.

## 6. Потеря карты

Если запись vault удалена (истёк срок, очистка), ответ остаётся с псевдонимами:
исходные значения восстановить невозможно. Это осознанный компромисс:
хранить карту бессрочно ради редкого восстановления опаснее, чем потерять
читаемость старого ответа.

## 7. Что проверено тестами

- Стабильность псевдонимов в области и независимость между областями.
- Шифротекст вместо открытых значений (проверка по содержимому БД).
- Восстановление после перезагрузки vault из базы.
- Отсутствие восстановления внутри URL и отсутствие рекурсии.
- Удаление секретов и невозможность их восстановления.
- Отправка провайдеру только псевдонимов (перехват тела запроса).

# Режимы защиты: сценарии, ограничения, переключение

Назначение: объяснить пользователю и сопровождающему, как работают четыре
режима, что они гарантируют и чего не гарантируют. Основание — ADR-0007 и
ADR-0008.

- Статус: реализованы `cloud_controlled`, `direct_cloud` и `protected_hybrid`;
  `local_only` доступен с явно помеченным локальным провайдером.
- Включение: `PROTECTION_MODES_ENABLED=1`. По умолчанию выключено, чтобы не
  показывать незавершённую функцию.
- Режим новых диалогов: `DEFAULT_PROTECTION_MODE=cloud_controlled`.

## 1. cloud_controlled — «Облако с предупреждениями»

- Исходный текст уходит выбранному провайдеру.
- Перед отправкой локальный `POST /protection/scan` находит категории данных;
  UI показывает их и предлагает отправить как есть, перейти в гибрид или
  отменить. Предупреждение не блокирует API: это UX-слой.
- Решение фиксируется в снимке сообщения (`cloud_scan.acknowledged`).

Когда подходит: данные не критичны, но хочется видеть, что именно уходит.

## 2. direct_cloud — «Прямой доступ»

- Текст уходит провайдеру без сканирования, псевдонимизации и предупреждений.
- Предназначен для задач без чувствительных данных: скорость важнее проверок.
- Бейдж в сообщении нейтрально-жёлтый и не выглядит защитой.
- Аудит отправки ведётся, как и в остальных режимах; текст в журнал не пишется.

Когда подходит: черновики, код без секретов, публичные данные.

## 3. protected_hybrid — «Защищённый гибрид»

- Локально: детекция, псевдонимизация, хранение карты, восстановление ответа.
- Наружу: только подтверждённый sanitized-текст.
- Пользователь видит preview: исходный текст, очищенный текст и список
  псевдонимов. Без подтверждения отправка невозможна.
- Ответ восстанавливается на хосте приложения; восстановленный текст не
  уходит обратно со следующим turn — для истории используется sanitized-версия.

Когда подходит: рабочие документы с названиями организаций, почтой, телефонами,
реквизитами, но нужен ответ внешней модели.

Ограничения:

- Это **минимизация и псевдонимизация**, а не анонимность. Модель всё ещё
  видит структуру текста, суммы и контекст.
- Детектор может пропустить сущность: preview обязателен именно поэтому.
- Псевдонимы вида `[ORG_1]` видны модели; она может ошибаться в их смысле.

## 4. local_only — «Только локально»

- Провайдер должен быть **явно помечен** пользователем как локальный
  (`is_local=true`): по `base_url` локальность не угадывается, потому что за
  `127.0.0.1` может стоять туннель в облако.
- В этом режиме отправка идёт локальному провайдеру (Ollama/LM Studio или
  собственный inference): псевдонимы не нужны, данные не покидают хост.
- Веб-поиск запрещён: это внешний запрос.
- `GET /api/v1/protection/local-runtime` честно сообщает, какие локальные
  модели объявлены. Доступность самого runtime проверяется при вызове:
  если Ollama не запущена, будет ошибка соединения, а не тихий переход в облако.
- Ограничения: автоматической egress-изоляции и проверки, что провайдер
  действительно локальный, пока нет — это ответственность развёртывания.

## 5. Переключение режима

- Режим выбирает пользователь в чате; административных ограничений нет.
- Смена режима увеличивает `protection_revision`, поэтому подготовка,
  сделанная до переключения, отклоняется.
- Режим хранится в диалоге. Новый диалог создаётся с `cloud_controlled`,
  но выбранный до создания режим применяется к первому сообщению.

## 6. Отказы и коды

| Ситуация | Ответ |
| --- | --- |
| флаг выключен | 400, `PROTECTION_MODES_ENABLED` |
| гибрид без подготовки | 400, `PROTECTION_PREPARATION_REQUIRED` |
| подготовка не подтверждена | 400, `PROTECTION_NOT_COMMITTED` |
| изменён digest | 409, `PROTECTION_DIGEST_MISMATCH` |
| изменился контекст/режим | 409, `PROTECTION_PREVIEW_STALE` |
| истёк срок подготовки | 410, `PROTECTION_PREPARATION_EXPIRED` |
| чужой диалог/подготовка | 404 |

## 7. Журнал операций

`GET /api/v1/protection/audit` возвращает последние события пользователя:
`prepare`, `commit`, `message_sent`. В журнал пишутся только метаданные
(идентификатор подготовки, ревизия, число сущностей, режим). Тексты сообщений
и исходные значения туда не попадают — журнал нужен для разбора инцидентов,
а не как вторая копия данных. Retention/очистка пока не автоматизированы.

## 8. Как выключить

`PROTECTION_MODES_ENABLED=0` и перезапуск api. Переключатель исчезает,
диалоги читаются как облачные, история не переписывается. Данные защиты
остаются в БД и не мешают работе.

## 9. Чего режимы не обещают

- Соответствия корпоративным политикам и сертификациям.
- Полной анонимности или необратимости.
- Замены ручной проверки: пользователь обязан смотреть preview.
- Денежных гарантий для моделей без цены (пока такие вызовы запрещены).

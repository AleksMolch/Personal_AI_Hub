# Потоки данных: что остаётся локально и что уходит наружу

Назначение: карта движения данных в защищённых режимах (ADR-0007). Документ
описывает **фактическое** поведение кода на HEAD, а не целевое.

- Дата: 2026-10-19
- Реализовано: режимы, детектор, vault, prepare/commit, гибридный чат,
  восстановление ответа, UI-переключатель (срезы 1–5)
- Не реализовано: `local_only` runtime, модель без цены (срез 6 откатан до
  проверки), ручная правка preview

## 1. Обозначения

- **Хост приложения** — машина, где запущены контейнеры (PostgreSQL, API,
  worker, Qdrant, BlobStore). Если приложение развёрнуто на сервере, данные
  покидают компьютер пользователя уже при загрузке в браузере.
- **Локально** в этом документе означает «на хосте приложения», а не «на
  устройстве пользователя».
- **Внешний вызов** — HTTP-запрос за пределы хоста приложения.

## 2. Таблица потоков

| Данные | Где хранятся | Уходят наружу | Когда |
| --- | --- | --- | --- |
| Приватный текст сообщения (`messages.content`) | PostgreSQL | **нет** в гибриде | — |
| Sanitized-текст (`messages.protection.sanitized`) | PostgreSQL | да, в гибриде | при отправке сообщения |
| Карта псевдонимов (`protection_entities`) | PostgreSQL, шифротекст | **нет** | — |
| Приватный digest подготовки | PostgreSQL | нет | — |
| Ключи провайдеров | PostgreSQL, шифротекст | нет | — |
| История для модели | собирается на лету | только sanitized-версии | каждый turn |
| Документы и чанки | BlobStore, PostgreSQL, Qdrant | нет (RAG-запрос для эмбеддингов — отдельно) | — |
| Запрос эмбеддингов | не хранится | текст запроса | RAG-поиск |
| Поисковый запрос (SearXNG) | не хранится | текст запроса к поисковым движкам | при включённом веб-поиске |
| URL страницы тарифов | не хранится | URL | импорт цен |
| Usage (токены) | PostgreSQL | нет | после вызова |
| Логи | файлы/stdout | нет | — |

## 3. Гибридный режим: путь одного сообщения

1. Пользователь пишет текст; браузер отправляет его только на свой API.
2. `POST /protection/.../prepare`: локальная детекция и санитизация.
   Провайдер не вызывается. Возвращаются приватный и sanitized preview.
3. Пользователь подтверждает preview.
4. `POST .../commit`: проверка digest и ревизии, статус `committed`.
   Наружу ничего не уходит.
5. `POST /conversations/{id}/messages`: сервер ещё раз сверяет digest с
   реальным payload, собирает историю из sanitized-версий и отправляет
   провайдеру только их.
6. Ответ модели приходит с псевдонимами, восстанавливается локально из vault
   и сохраняется: `content` — для пользователя, `protection.sanitized` — для
   следующего turn.
7. Ревизия диалога увеличивается: старый preview больше не действителен.

## 4. Что не уходит даже в облачном режиме

- Vault и расшифрованные значения: API не имеет эндпоинта, возвращающего
  исходные значения; восстановление выполняется внутри процесса при показе.
- Ключи провайдеров: только шифротекст, открытый ключ не логируется.
- Приватные сообщения при включённом гибриде: провайдер получает только
  sanitized-текст (проверено перехватом тела запроса в интеграционном тесте).

## 5. Известные пределы

- Детекция эвристическая: имена людей, нестандартные реквизиты и часть
  адресов могут не распознаваться.
- В режиме `cloud_controlled` исходный текст уходит провайдеру целиком —
  это осознанный выбор пользователя, а не ошибка.
- Веб-поиск и импорт тарифов в `local_only` не запрещены кодом, потому что
  режим ещё не включён: до среза 6 он недоступен.
- Загрузка файлов в браузере уже передаёт данные на хост приложения.

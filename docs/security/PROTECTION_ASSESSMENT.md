## 4. Инварианты, которые нельзя нарушить при реализации

1. Пользователь сам выбирает режим; никаких административных ограничений.
2. Оригиналы, OCR, карта псевдонимов и восстановление остаются на хосте
   приложения. Наружу уходит только подтверждённый sanitized payload.
3. Внутри выбранного режима правила соблюдаются строго; при невозможности
   подготовить запрос предлагается локальная обработка или явное переключение,
   но не автоматическое ослабление.
4. Восстановление — точное совпадение токенов, без рекурсии; восстановленные
   значения не отправляются обратно в облако следующим turn.
5. Модель без цены допустима: `usage` сохраняется, стоимость `unknown`, а не 0;
   предупреждение видно, гарантий денежного лимита нет.
6. UI не обещает анонимность и соответствие корпоративным политикам; «локально»
   означает «на хосте приложения», а не «на вашем устройстве», если приложение
   развёрнуто на сервере.

## 5. Наблюдения, влияющие на дизайн

- `Message.content` хранит полный текст и используется как история следующего
  turn — значит гибриду нужны два представления: приватное (для пользователя)
  и sanitized (для отправки). Иначе восстановленные значения уйдут обратно.
- Резервирование бюджета сейчас требует цену (`PRICE_REQUIRED`). Для модели без
  цены нужно отдельное поведение: `UsageRecord.cost_amount = NULL`,
  `cost_state = unknown`, а проверка лимита помечается как «не гарантируется».
- `Message.model_snapshot` — готовое место для метаданных защиты (режим,
  preparation id, метод восстановления), миграция не требуется для истории.
- E2E-стек уже проверяет axe и клавиатуру — новые экраны обязаны сохранить этот
  уровень.

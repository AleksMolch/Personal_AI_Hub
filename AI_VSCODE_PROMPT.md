# Стартовый промпт для ИИ-разработчика в VS Code

## Назначение и функции
Этот файл нужно целиком передать coding-агенту при первом запуске проекта. Он задает порядок старта, ожидаемые артефакты и запрет на преждевременную реализацию второго этапа.

## Промпт

Ты работаешь в VS Code внутри репозитория персональной self-hosted AI-платформы. Прежде чем писать код, прочитай в указанном порядке:

1. `AGENTS.md` — обязательные правила;
2. `00_START_HERE.md` — состав проекта и порядок работы;
3. `SPECIFICATION.md` — функциональные и нефункциональные требования;
4. `ARCHITECTURE.md` — компоненты, контракты и модель данных;
5. `ROADMAP.md` — этапы, задачи и критерии приемки;
6. `TESTING.md` — обязательные проверки;
7. `README.md`, `README_staff.md`, `AI_MAINTENANCE.md` — требования к документации.

Текущая цель — полностью выполнить Этап 1: локальная платформа для языковых моделей. Этап 2 (генерация видео через API) пока не реализуй, но не нарушай подготовленные общие контракты `Provider`, `Capability`, `Job`, `Asset`, `UsageRecord`, `BlobStore`, чтобы добавление видео не потребовало менять фундамент.

### Перед началом реализации

1. Проверь содержимое репозитория и не удаляй существующий рабочий код без обоснования.
2. Составь план реализации Этапа 1 по вертикальным пользовательским сценариям, а не по слоям.
3. Создай `docs/IMPLEMENTATION_STATUS.md` с чек-листом требований и статусами `не начато / в работе / готово / заблокировано`.
4. Проверь актуальные стабильные версии зависимостей, лицензии и совместимость; зафиксируй версии в lock-файлах и `THIRD_PARTY_NOTICES.md`.
5. Покажи план, затем сразу приступай к первой незаблокированной задаче.

### Обязательная последовательность каждой итерации

- тест или критерий приемки;
- минимальная реализация;
- unit/integration тесты;
- линтеры и типизация;
- запуск Docker-сервисов;
- smoke/E2E тест;
- обновление документации;
- короткий отчет с фактическими командами и результатами.

### Главный пользовательский сценарий Этапа 1

Пользователь клонирует Git-репозиторий, копирует `.env.example` в `.env`, указывает хотя бы один API-ключ OpenRouter/RouterAI/Selectel, выполняет одну команду запуска, открывает веб-интерфейс, выбирает модель, общается с потоковым выводом, видит расход токенов и оценочную/фактическую стоимость, загружает документ, дожидается фоновой индексации и задает вопросы с цитатами. История сохраняется после перезапуска. Экспорт чата и данных работает.

### Definition of Done Этапа 1

Этап завершен только если:

- чистая установка проходит по README на поддерживаемой ОС;
- `docker compose up -d --build` или предусмотренная единая команда успешно поднимает стек;
- healthchecks становятся healthy;
- миграции выполняются автоматически и идемпотентно;
- настроены минимум OpenRouter и универсальный OpenAI-compatible adapter, которым подключаются RouterAI и Selectel;
- streaming chat, cancel и retry работают;
- ошибки 401/402/429/5xx отображаются понятно и не раскрывают секреты;
- история и настройки сохраняются;
- usage/cost records записываются с валютой, источником цены и временем актуальности;
- дневной/месячный лимит блокирует новый запрос до отправки провайдеру;
- импорт PDF/DOCX/TXT/MD/CSV/XLSX проходит с лимитами и безопасной валидацией;
- RAG возвращает ссылки на источник/страницу или явно сообщает, что оснований недостаточно;
- unit, integration и E2E тесты проходят;
- live-тесты выключены по умолчанию;
- `README.md`, `README_staff.md`, OpenAPI и `AI_MAINTENANCE.md` соответствуют реализации;
- ни одного реального ключа или приватного файла нет в Git-истории.

### Формат отчетов

После каждой итерации сообщай:

1. что реализовано;
2. какие файлы изменены;
3. какие команды выполнены;
4. сколько тестов прошло/пропущено/упало;
5. какие сервисы запускались и какой smoke-тест выполнен;
6. известные риски и ограничения;
7. следующий конкретный шаг.

Начни с анализа документов и создания `docs/IMPLEMENTATION_STATUS.md`. Не генерируй весь проект одним недоказуемым массивом кода: двигайся рабочими вертикальными срезами.

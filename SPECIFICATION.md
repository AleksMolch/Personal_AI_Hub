# Техническое задание: персональная AI-платформа

## Назначение и функции
Документ фиксирует требования, границы продукта и критерии ожидаемого поведения. Coding-агент не должен подменять требования догадками.

## Цели
- Заменить несколько подписок оплатой фактического API-потребления.
- Объединить OpenRouter, RouterAI, Selectel и совместимые endpoints.
- Локально хранить настройки, историю, документы, индексы, расходы и готовые медиа.
- Разворачиваться одной командой и обновляться с миграциями/backup.
- На Этапе 2 добавить video generation без смены модели данных и очереди задач.

## Не входит в Этап 1
- Локальный inference больших генеративных моделей.
- Публичный SaaS и биллинг пользователей.
- Сложные автономные агенты, способные бесконтрольно расходовать бюджет.
- Генерация и монтаж видео.
- Мобильное приложение.

## Пользователь и режим доступа
MVP рассчитан на одного владельца. Должны существовать два режима:
- `local`: привязка к localhost, первая установка создает администратора;
- `lan`: обязательная авторизация и явное разрешение внешнего bind.

Модель данных обязана иметь `user_id`, чтобы multi-user можно было добавить миграциями, но UI командной работы не нужен.

## Этап 1: функции

### Настройка провайдеров
- CRUD провайдера: название, тип адаптера, base URL, зашифрованный ключ, валюта, priority, enabled.
- Предустановки OpenRouter, RouterAI и Selectel; универсальный OpenAI-compatible preset.
- Проверка соединения без сохранения ответа как пользовательского чата.
- Получение `/models`, когда поддерживается; ручное создание model profile иначе.
- Capabilities модели: chat, streaming, tools, vision, embeddings, structured output; video зарезервировано.

### Чат
- Создание, переименование, поиск, архивирование и удаление диалога.
- Потоковый ответ SSE; stop/cancel.
- Системная инструкция, temperature, max output, модель.
- Повтор ответа, редактирование сообщения с созданием ветки.
- Markdown, кодовые блоки, copy/download.
- Экспорт диалога в Markdown и JSON; импорт собственного JSON-формата с версией schema.
- Нормализованные ошибки 401, 402, 403, 404 model, 429, timeout, 5xx.

### Usage, цены и бюджеты
- Сохранять input/output/cached/reasoning tokens, latency, provider request id, модель и источник usage.
- Цена модели — versioned price snapshot: валюта, effective_at, source URL/manual/API, вход/выход/cache/video units.
- До запроса показывать оценку; после — фактическую стоимость при наличии usage.
- Если провайдер не вернул usage, статус стоимости `estimated`, а не `actual`.
- Дневной и месячный hard limit проверяется до вызова; резервируется оценочная сумма для параллельных jobs.
- Конвертация валют только с сохранением курса, источника и времени; нельзя молча смешивать RUB/USD.

### Файлы и RAG
- Форматы MVP: TXT, MD, PDF text layer, DOCX, CSV, XLSX. OCR сканов — опциональный профиль Этапа 1 после базового импорта.
- Безопасные лимиты размера, числа листов/страниц, archive bombs; исполняемые файлы запрещены.
- Импорт создает `Asset` и `Job`; worker извлекает текст, чанкует, получает embeddings, пишет Qdrant.
- Каждый chunk хранит source asset, страницу/лист, диапазон и checksum.
- RAG ответ содержит цитаты. При низкой релевантности модель должна сообщать недостаточность источников.
- Смена embedding model создает новую версию индекса, а не смешивает векторы.
- Удаление документа удаляет связанные chunks/vectors через идемпотентную job.

### Таблицы
- Просмотр схемы CSV/XLSX, листов, типов и первых строк.
- Анализ через DuckDB в изолированном read-only workflow.
- Модель получает schema и агрегированные результаты, а не всю таблицу.
- Запрещены произвольные файловые функции/сетевые расширения DuckDB.
- Экспорт результата CSV/XLSX.

### Администрирование
- Dashboard: расходы сегодня/месяц, токены, ошибки, latency, активные jobs.
- Просмотр jobs с retry/cancel там, где это безопасно.
- Backup/restore скрипты и версия backup manifest.
- Health: API, DB, Valkey, Qdrant, storage, worker.

## Этап 2: функции video generation
- Провайдеры-адаптеры: OpenRouter video API и/или прямые API Veo, Seedance, Kling, Sora по доступным официальным контрактам.
- Text-to-video и image-to-video в зависимости от capability.
- Параметры через provider-specific schema: duration, resolution, aspect ratio, audio, seed, reference asset.
- Предварительная оценка цены и обязательное подтверждение выше настраиваемого порога.
- Async job lifecycle: queued → submitted → running → downloading → processing → completed/failed/cancelled/expired.
- Webhook с проверкой подписи; polling fallback с backoff.
- Сохранение исходного результата до истечения URL провайдера.
- Галерея, превью, метаданные, download/delete.
- FFmpeg: probe, thumbnail, faststart, безопасная нормализация контейнера; сложный editor не входит в первый релиз Этапа 2.
- Повтор платной задачи только после проверки idempotency/status; нельзя автоматически создать вторую платную генерацию после неизвестного timeout.

## Нефункциональные требования
- Поддержка актуальных Windows+Docker Desktop, Linux Docker Engine; macOS best effort.
- Idle RAM целевого Этапа 1: до 4 GB без OCR; запуск возможен на 8 GB, рекомендовано 16 GB.
- Этап 2 API-only не требует GPU; рекомендуемый диск 500 GB+.
- First meaningful paint UI <3 сек на локальной машине после прогрева.
- API p95 внутренних операций без внешней модели <500 мс.
- Все списковые endpoints имеют pagination.
- Логи структурированные JSON, correlation/request/job id.
- Telemetry выключена по умолчанию.
- Доступность интерфейса: keyboard navigation, labels, contrast, понятные ошибки.

# Передача проекта coding-агенту

## Назначение и функции
Документ объясняет состав пакета, порядок передачи в VS Code и ожидаемый результат. Это точка входа для человека и ИИ.

## Продукт
Персональная self-hosted веб-платформа с собственными API-ключами. Этап 1 объединяет LLM-провайдеров, чат, расходы, документы, OCR, таблицы и RAG. Этап 2 добавляет генерацию видео через API Veo, Seedance, Kling, Sora и других провайдеров, не заменяя ядро Этапа 1.

## Порядок работы
1. Поместить все файлы пакета в корень нового Git-репозитория.
2. Открыть каталог в VS Code.
3. Убедиться, что coding-агенту разрешены редактирование файлов, терминал, Docker и локальные тестовые команды.
4. Передать агенту содержимое `AI_VSCODE_PROMPT.md`.
5. Агент должен соблюдать `AGENTS.md` на всех последующих сессиях.
6. Разрабатывать только Этап 1 до выполнения его release gate.

## Состав пакета
- `AGENTS.md` — постоянные правила для coding-агента.
- `AI_VSCODE_PROMPT.md` — первый промпт.
- `SPECIFICATION.md` — требования продукта.
- `ARCHITECTURE.md` — компоненты, данные и API-контракты.
- `ROADMAP.md` — два этапа и backlog.
- `TESTING.md` — тесты, команды и приемка.
- `README.md` — шаблон публичной пользовательской документации.
- `README_staff.md` — эксплуатация и диагностика.
- `AI_MAINTENANCE.md` — инструкция будущему ИИ сопровождения.

## Ожидаемая структура репозитория
```text
.
├── AGENTS.md
├── README.md
├── README_staff.md
├── AI_MAINTENANCE.md
├── apps/
│   ├── web/                  # Next.js UI
│   ├── api/                  # FastAPI и бизнес-логика
│   └── worker/               # Celery jobs
├── packages/
│   └── contracts/            # Сгенерированные TS-типы/OpenAPI-клиент
├── infra/
│   ├── compose/              # Docker Compose
│   └── scripts/              # setup, backup, restore, smoke
├── docs/
│   ├── adr/                  # Architecture Decision Records
│   ├── api/                  # API и webhook docs
│   └── IMPLEMENTATION_STATUS.md
├── tests/
│   ├── integration/
│   ├── e2e/
│   └── fixtures/
├── .env.example
├── compose.yaml
├── Makefile
└── THIRD_PARTY_NOTICES.md
```

Блок структуры задает границы модулей. Общие контракты не должны дублироваться между frontend и backend: TypeScript-клиент генерируется из OpenAPI.

## Принцип «10 минут»
Под «10 минут» понимается первый запуск на уже установленном Docker Desktop/Engine: clone → `.env` → один API-ключ → одна команда → healthcheck → web UI. Загрузка образов зависит от сети и не гарантируется по времени.

## Приоритеты
1. Корректность расходов и отсутствие утечки ключей.
2. Рабочая установка и восстановление данных.
3. Надежный чат и RAG.
4. Расширяемость провайдеров.
5. Удобство UI.
6. Дополнительные функции.

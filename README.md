# Personal AI Hub — локальный интерфейс к LLM и Video AI

## Назначение и функции документа
README предназначен для обычного пользователя и публикации в Git. Он объясняет возможности, системные требования, быстрый запуск, настройку ключей, обновление, backup и ограничения без знания внутренней архитектуры.

## Что делает приложение
На Этапе 1 (текущий релиз):
- единый чат с OpenRouter, RouterAI, Selectel и любым OpenAI-compatible API;
- потоковые ответы, остановка генерации и история;
- контроль токенов, цен и дневного/месячного бюджета;
- стоимость каждого ответа прямо в чате (с пометкой «оценка» или «факт»);
- экспорт диалогов в Markdown/JSON;
- базы знаний и RAG: загрузка PDF, DOCX, TXT, Markdown с цитатами;
- анализ таблиц CSV/XLSX (схема, SQL-запросы, экспорт);
- фоновые задачи с отменой/повтором;
- локальное хранение данных.

Дополнительно (включается отдельно):
- **веб-поиск** для обоснования ответов источниками (`make up-search`,
  см. «Веб-поиск» ниже);
- **управление глубиной рассуждений** для моделей, которые это поддерживают.

Этап 2 (генерация видео через Veo/Seedance/Kling/Sora) не входит в текущий релиз;
интерфейс показывает только реально доступные возможности.

## Важно о приватности и стоимости
Приложение self-hosted, но запросы к внешним моделям отправляются выбранному API-провайдеру. Пользователь самостоятельно оплачивает API и соблюдает его условия. Локальное хранение не делает внешнюю генерацию полностью приватной.

## Системные требования
Этап 1: 4–6 CPU cores, минимум 8 GB RAM, рекомендовано 16 GB, 50–120 GB свободного SSD. Этап 2 API-only: GPU не нужен; рекомендуется 500 GB+ для видео. Нужны Docker Engine/Compose или Docker Desktop.

## Быстрый запуск
```bash
git clone <ACTUAL_REPOSITORY_URL>
cd <ACTUAL_DIRECTORY>
make bootstrap
make up
```

Пояснение блока: `make bootstrap` проверяет Docker, создаёт `.env` со случайными
секретами (мастер-ключ и пароль БД) и собирает образы; `make up` поднимает стек
и ждёт готовности. `.env` можно создать и вручную из `.env.example`.

Откройте `http://localhost:3000`. При первом входе создайте администратора
(вкладка «Первый запуск»), затем добавьте API-провайдера в разделе «Провайдеры»,
синхронизируйте модели и задайте цену модели в настройках.

## Подключение провайдеров
- OpenRouter: base URL и ключ из личного кабинета.
- RouterAI: OpenAI-compatible base URL и собственный ключ.
- Selectel: endpoint и ключ из панели ИИ-роутера.
- Другой OpenAI-compatible API: ручной base URL, ключ и модели.

Не помещайте ключи в screenshots, issues и Git. Приложение должно показывать только маску ключа.

## Основные операции
### Чат
В разделе «Чат» создайте диалог, выберите модель и отправьте сообщение. Ответ
идёт потоком; кнопка «Стоп» отменяет генерацию. История сохраняется после
перезапуска. Экспорт диалога доступен через API (`GET /api/v1/conversations/{id}/export`).

### Документы и RAG
В разделе «Базы знаний» создайте базу, выбрав embedding-модель, загрузите
документ (PDF/DOCX/TXT/MD или изображение PNG/JPG/TIFF/WEBP/BMP — сканы
распознаются автоматически). Дождитесь завершения фоновой задачи (раздел
«Задачи»), затем задайте вопрос — ответ вернёт цитаты с указанием документа
и страницы. При низкой релевантности система сообщит о недостаточности
источников. Для embedding-модели обязательно задайте `PriceSnapshot`
(страница «Модели»): без цены индексация завершается ошибкой `PRICE_REQUIRED`,
а RAG-запрос возвращает 400 — платные вызовы не уходят без контроля бюджета,
как и в чате.

### Таблицы
В разделе «Таблицы» загрузите CSV/XLSX, просмотрите схему и выполните SQL-запрос
(только SELECT) — результат можно экспортировать в CSV/XLSX.

### Расходы
В разделе «Расходы» показаны траты за день/месяц, токены и лимиты. Стоимость
помечается `estimated` (если провайдер не вернул usage) или `actual`. Дневной и
месячный hard limit блокирует новый запрос до отправки провайдеру.

### Веб-поиск (опционально)
Позволяет обосновать ответ свежими источниками из интернета. Требует отдельного
локального сервиса: без него чат работает как обычно, а переключатель «Веб» не
показывается.

```bash
make up-search     # поднять SearXNG
# затем в .env: WEB_SEARCH_ENABLED=1 и SEARXNG_URL=http://searxng:8080
docker compose up -d api
```

Пояснение блока: `make up-search` запускает локальный meta-поисковик SearXNG
(отдельный compose-профиль, порт только на 127.0.0.1), после чего веб-поиск
включается переменной окружения и перезапуском API. Поиск бесплатный и не
требует новых ключей; найденные страницы попадают во вход запроса, поэтому
число результатов и длина фрагментов ограничены настройками. На одно сообщение
выполняется не более одного поиска, а при сбое поиска платный вызов не
происходит. Источники показываются под ответом с номерами, совпадающими с
маркерами `[n]` в тексте. Выключить: `WEB_SEARCH_ENABLED=0` и
`make down-search`.

### Профиль
В разделе «Профиль» видны имя пользователя, права и идентификатор записи, а
также краткое описание того, как устроены вход и хранение секретов.

## Команды управления
```bash
make status
make logs
make down
make up
make test
make smoke
make backup
make restore FILE=/path/to/backup.tar.gz
```

Пояснение блока: `status` показывает контейнеры и health; `logs` помогает
диагностике; `down/up` перезапускают; `test` выполняет бесплатные проверки;
`smoke` проверяет поднятый локальный экземпляр; `backup` создаёт архив данных в
`backups/`; `restore` восстанавливает (требует подтверждения). Опциональные
возможности включаются отдельно: `make up-search` — веб-поиск,
`make up-litellm` — прокси LiteLLM.

## Обновление
```bash
make backup
make down
make up        # пересобирает образы и применяет миграции
make smoke
```

Пояснение блока: сначала создается backup, затем обновляются образы и применяются
миграции (автоматически при старте API), после чего smoke-тест подтверждает
базовый сценарий.

## Удаление
Остановка без удаления данных: `make down`. Полное удаление (включая все данные
и базы) требует явного удаления Docker-томов:
```bash
make down
docker volume rm personal-ai-hub_pgdata personal-ai-hub_qdrantdata personal-ai-hub_valkeydata personal-ai-hub_assets
```
Эта команда необратимо уничтожает данные — выполняйте только после backup и
осознанно.

## Частые проблемы
- Неверный ключ: проверить provider test и баланс.
- 429: дождаться Retry-After или сменить endpoint; не создавать бесконечный retry.
- Модель отсутствует: синхронизировать каталог или создать profile вручную.
- RAG без цитат: проверить завершение ingest job и embedding profile.
- Недостаточно места: очистить ненужные assets только через UI/команду приложения.
- «Не удалось связаться с API» при входе: открыть приложение по тому же адресу,
  что указан в `APP_BASE_URL` (по умолчанию `http://localhost:3000`).
  `localhost` и `127.0.0.1` — для браузера разные адреса; оба варианта
  поддерживаются, но если вы меняли `APP_BASE_URL` на внешний домен, вход
  с другого адреса заблокирует CORS.

## Безопасный внешний доступ
По умолчанию сервис доступен только локально. Для LAN/Internet агент должен документировать HTTPS, авторизацию, firewall и reverse proxy. Нельзя советовать просто открыть порт API наружу.

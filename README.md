# Personal AI Hub — локальный интерфейс к LLM и Video AI

> Этот README является обязательным шаблоном публичной документации. Coding-агент должен заменить незавершенные места фактическими командами и удалить это примечание перед релизом.

## Назначение и функции документа
README предназначен для обычного пользователя и публикации в Git. Он объясняет возможности, системные требования, быстрый запуск, настройку ключей, обновление, backup и ограничения без знания внутренней архитектуры.

## Что делает приложение
На Этапе 1:
- единый чат с OpenRouter, RouterAI, Selectel и OpenAI-compatible API;
- потоковые ответы и история;
- контроль токенов, цены и бюджета;
- импорт/экспорт диалогов;
- работа с PDF, DOCX, TXT, Markdown, CSV и XLSX;
- фоновые задачи, RAG и цитаты из документов;
- локальное хранение данных.

На Этапе 2:
- генерация видео через API Veo, Seedance, Kling, Sora и доступные агрегаторы;
- очередь задач, стоимость до запуска, галерея и локальное сохранение результатов;
- базовая post-processing обработка.

Этап 2 может отсутствовать в текущем релизе. Интерфейс обязан явно показывать фактически доступные возможности.

## Важно о приватности и стоимости
Приложение self-hosted, но запросы к внешним моделям отправляются выбранному API-провайдеру. Пользователь самостоятельно оплачивает API и соблюдает его условия. Локальное хранение не делает внешнюю генерацию полностью приватной.

## Системные требования
Этап 1: 4–6 CPU cores, минимум 8 GB RAM, рекомендовано 16 GB, 50–120 GB свободного SSD. Этап 2 API-only: GPU не нужен; рекомендуется 500 GB+ для видео. Нужны Docker Engine/Compose или Docker Desktop.

## Быстрый запуск
```bash
git clone <ACTUAL_REPOSITORY_URL>
cd <ACTUAL_DIRECTORY>
make bootstrap
make up
```

Пояснение блока: `make bootstrap` проверяет Docker, создаёт `.env` со случайными
секретами (мастер-ключ и пароль БД) и собирает образы; `make up` поднимает стек
и ждёт готовности. `.env` можно создать и вручную из `.env.example`.

Откройте `http://localhost:3000`. Первый вход и добавление API-провайдера
(раздел «Настройки → Провайдеры») реализуются на следующих срезах Этапа 1.

## Подключение провайдеров
- OpenRouter: base URL и ключ из личного кабинета.
- RouterAI: OpenAI-compatible base URL и собственный ключ.
- Selectel: endpoint и ключ из панели ИИ-роутера.
- Другой OpenAI-compatible API: ручной base URL, ключ и модели.

Не помещайте ключи в screenshots, issues и Git. Приложение должно показывать только маску ключа.

## Команды управления
```bash
make status
make logs
make down
make up
make test
make backup
```

Пояснение блока: `status` показывает контейнеры и health; `logs` помогает диагностике; `down/up` перезапускают; `test` выполняет бесплатные проверки; `backup` создает архив данных. Агент обязан документировать путь backup и retention.

## Обновление
```bash
make backup
make update
make smoke
```

Пояснение блока: сначала создается backup, затем обновляются образы/миграции, после чего smoke-тест подтверждает базовый сценарий. Update script обязан прекращать работу при ошибке миграции и сообщать способ rollback.

## Удаление
Документировать отдельно остановку и удаление данных. Команда уничтожения volumes не должна выглядеть как обычный uninstall и обязана требовать явного подтверждения.

## Частые проблемы
- Неверный ключ: проверить provider test и баланс.
- 429: дождаться Retry-After или сменить endpoint; не создавать бесконечный retry.
- Модель отсутствует: синхронизировать каталог или создать profile вручную.
- RAG без цитат: проверить завершение ingest job и embedding profile.
- Недостаточно места: очистить ненужные assets только через UI/команду приложения.

## Безопасный внешний доступ
По умолчанию сервис доступен только локально. Для LAN/Internet агент должен документировать HTTPS, авторизацию, firewall и reverse proxy. Нельзя советовать просто открыть порт API наружу.

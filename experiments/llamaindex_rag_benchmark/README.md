# LlamaIndex RAG benchmark (PROTOTYPE ONLY)

Назначение: изолированное сравнение нативного RAG Personal AI Hub и LlamaIndex
по объективным метрикам на синтетическом наборе документов. Это выполнение
Итерации 5 из `IMPROVEMENT_TASKS_FOR_CODING_AI.md` и ADR-0003: LlamaIndex
остаётся **только** в этом каталоге и не входит в production-зависимости.

## Что сравнивается

| Pipeline | Chunking | Хранилище | Эмбеддинг |
| --- | --- | --- | --- |
| `current` | `personal_hub.chunking.chunk_document` (окно 2000/200 символов) | `InMemoryVectorStore` проекта (та же cosine-логика, что в Qdrant-пути) | локальный hash-эмбеддинг |
| `llamaindex` | `SentenceSplitter(chunk_size=2000, chunk_overlap=200, tokenizer=chars)` | `SimpleVectorStore` (in-memory, Qdrant не задействован) | тот же локальный hash-эмбеддинг |

Оба pipeline используют один и тот же детерминированный hash-эмбеддинг, чтобы
сравнение изолировало chunking/retrieval, а не качество модели эмбеддингов.
Платные API не вызываются; live-тесты по умолчанию запрещены.

## Метрики

- **recall@k (документ)** — ожидаемый документ присутствует в top-k;
- **recall@k (факт)** — в top-k есть чанк ожидаемого документа с ожидаемым фактом;
- **MRR** — обратный ранг первого чанка ожидаемого документа;
- **top-1 цитата** — первый хит принадлежит ожидаемому документу;
- **отказ (неотвечаемые)** — все хиты ниже `MIN_RELEVANCE` (0.30) для вопросов,
  ответа на которые в корпусе нет;
- **latency** — среднее и медиана на запрос (включая эмбеддинг запроса);
- **RAM** — пик Python-аллокаций (tracemalloc) на построение индекса и запросы;
- **чанков** — сколько чанков построено.

## Как запустить

```bash
experiments/llamaindex_rag_benchmark/run.sh
```

Скрипт поднимает одноразовый `python:3.12-slim`, ставит зависимости из
`requirements.txt` (LlamaIndex в проект не устанавливается) и печатает таблицу;
машиночитаемые результаты складываются в `results.json` (git-ignored).

Требуется только Docker и сеть для `pip install` (или заранее собранный образ).

## Ограничения эксперимента

- Корпус синтетический и маленький (10 документов, 17 вопросов): метрики
  показывают поведение chunking/retrieval, а не качество на реальных данных.
- Hash-эмбеддинг лексический: перефразировки без общих слов одинаково плохи
  для обоих pipeline; вывода о качестве эмбеддингов эксперимент не даёт.
- `SentenceSplitter` запускается с character-level tokenizer (эквивалент
  окон проекта, без загрузки tiktoken-словаря из сети).
- Пик RAM из `tracemalloc` учитывает Python-аллокации и не равен RSS
  процесса; сравнение относительно, а не абсолютно.

## Что делать с результатами

Выводы и решение (переносить ли что-то в production, добавлять ли зависимость)
фиксируются в `docs/IMPROVEMENTS_ASSESSMENT.md` (Task 5.3). Любое переносимое
улучшение внедряется нативно и отдельным ADR; каталог `experiments/` можно
удалить без влияния на production.
